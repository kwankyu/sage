Overview
========

Sage documentation build process is complicated. It is a challenging task for the Sage
development community to maintain the documentation.

The builder ReferenceSubBuilder is responsible in updating the files in
`src/doc/en/reference/sub/sage/...`. It searches all `rst` files in
`src/doc/en/reference/sub` (except those under `sage/`) and collects all module names:

.. code-block:: RST

     ..toctree::
        :maxdepth: 1

        ssage/coding

For the example `sage/xxx`, the builder plans `src/doc/en/reference/sub/sage/xxx.rst` file.
The file is of this form:

.. code-block:: RST

    .. nodoctest

    .. _sage.knots.link:

    Links
    =====

    .. This file has been autogenerated.


    .. automodule:: sage.knots.link
       :members:
       :undoc-members:
       :show-inheritance:

Then Sphinx works for `src/doc/en/reference/sub`, and output files into
`local/share/doc/sage/html/en/reference/sub` for html target.

When doc is built by `make doc-html`, the doc is built twice: once for `inventory` target
and then `html` target. The output for `inventory` target is written to
`local/share/doc/sage/inventory/en/reference/sub`. When Sphinx read the source files,
it constructs doctrees in `local/share/doc/sage/doctrees/en/reference/sub`. A doctree
file has the form `xxx.doctree`, and is an internal intermediate data file corresponding
to the source file. Sphinx also output `environment.pickle` in
`local/share/doc/doctrees/en/reference/sub/environment.pickle`. This environment file
has all sorts of metadata about the source files.

The doc builder references the environment file to update the files in
`src/doc/en/reference/sub/sage/...`. For example, a source file `src/sage/coding/ag_code.py`
is modified. THen the doc builder detects this and updates the tempstamp of
`src/doc/en/reference/sub/sage/coding/ag_code.rst`. This causes Sphinx to rebuild the output
for this rst file.
